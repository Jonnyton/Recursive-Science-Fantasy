# Writer Boundary

## Purpose

Keep the fantasy writer product narrowly specialized.

## The writer is allowed to do

- write outlines
- write chapters
- revise text
- improve scene transitions
- strengthen dialogue
- maintain character voice
- maintain series voice
- use approved personas
- use approved craft cards
- use approved canon excerpts

## The writer is not allowed to do

- browse the web
- read raw research notes
- inspect judge prompts
- inspect scoring thresholds
- edit architecture
- edit eval logic
- edit governance rules
- change budgets
- manage git
- approve proposals
- redesign memory systems

## Allowed inputs

- current `writing_system.md`
- one or more approved persona overlays
- scenario brief
- approved canon/state excerpt
- approved craft cards
- approved exemplars
- revision target for the current pass

## Forbidden inputs

- raw experiment backlog unless distilled into craft cards
- architecture proposals
- frontier review notes
- online research dumps
- evaluator internals
- proposal manifests outside the writer lane

## Product invariant

The writer product should get better at writing, not broader at being an agent.

If a proposed improvement mainly makes the writer more general-purpose, reject it from the product plane and keep it in the control plane.
